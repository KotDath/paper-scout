# Paper Scout — сдача дня 35

Paper Scout помогает исследователю находить и разбирать публикации о долговременной памяти AI-агентов. Пользователь задаёт вопрос во Flutter, получает отчёт на русском с исходными фрагментами, сохраняет статью и заметку, затем возвращается к ним в следующем вопросе.

AI участвует во всём исследовании: DeepSeek Chat Completions выбирает поисковые запросы и инструменты, анализирует последовательные части доступного текста и формирует ответ с evidence IDs. Собственный Go AgentRunner сохраняет историю и ограничивает расход. Для уточнений работает гибридный RAG: SQLite FTS5/BM25 + Qwen3 embeddings в существующей Ollama + RRF. Агентных библиотек нет.

**Результат:** Go API и Android Flutter-клиент реализованы; реальный проход с arXiv, DeepSeek и Ollama проверен в T16 и повторён для видео в T17. Два аккаунта имеют отдельные профили, историю, библиотеку и заметки. В объём входит только день 35; поддержка/FAQ/CRM/MCP и публичный деплой не входят.

## Локальный запуск

Нужны Go 1.26+, Flutter/Android SDK, Poppler, работающая Ollama с установленной `qwen3-embedding:0.6b` и серверная конфигурация DeepSeek/двух аккаунтов. Все команды выполняются из текущей worktree. Для T22 это `/home/kotdath/omp/personal/ai/paper-scout-worktrees/T22`, ветка `dag/t22`.

1. Настроить локальные каталоги сборок и конфигурацию по [runbook](docs/local-development.md#подготовка).
2. Собрать `cmd/paper-scout`, выполнить `-seed`, запустить API с loopback-портом `0` и постоянной локальной БД — [точные команды](docs/local-development.md#go-api-и-два-аккаунта).
3. Собрать APK, установить на доступный эмулятор, настроить `adb reverse` на фактический порт и ввести origin на экране входа — [Flutter](docs/local-development.md#flutter-на-android).
4. Войти, задать интересы, создать диалог, запустить исследование. Открыть coverage и исходный фрагмент; задать follow-up, сохранить заметку. После рестарта войти снова. Для смены аккаунта использовать «Профиль» → выход.

Общий интеграционный набор: `python3 -B integration/check.py`. Он использует внешние HTTP fixtures и настоящую локальную Qwen3; официальные arXiv/DeepSeek вызываются только отдельным явным `--live` запуском. См. [границы проверок](integration/README.md). Unit/widget tests запрещены и отсутствуют.

## Ограничения

`complete` означает анализ всего **извлечённого текста**, без OCR, понимания изображений и гарантии сохранения формул. `partial` и `abstract_only` отображаются отдельно от готовности индекса; retrieval не доказывает полного чтения. В T16 были partial-анализ, ошибочный ID и неточная подпись числового диапазона; принятый результат получен полным повторным анализом и проверенным follow-up. T17 прошёл без неудачных AI-запусков. Сверка трёх утверждений одной статьи не гарантирует научную точность любого ответа.

Токен Flutter хранится в памяти: после остановки приложения нужен новый вход. Сервер сохраняет данные, а незавершённые production run после рестарта становятся `interrupted` без платного replay. Недоступная Ollama даёт явный lexical-only режим, который не проходит гибридную приёмку. Видео, БД и кэш локальные; перенос и резервное копирование описаны в runbook.
