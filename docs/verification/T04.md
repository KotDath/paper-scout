## Limits and handoff

- The live check proves real metadata, versions and cache/source identity. It
  does not prove HTML/PDF availability, extraction, model reading, retrieval or
  ownership; those belong to later nodes. Provider failure/date-range scenarios
  were checked through HTTP fixtures, not induced against live arXiv.
- The limiter is process-local for the planned single Go server. It does not
  coordinate independent processes or survive server restart. Redirects are
  rejected entirely, so a future arXiv redirect policy change needs review.
- T11 must instantiate the adapter on the shared store, validate tool arguments,
  account for `Result.Attempts` even on errors, and create user/run membership
  when importing. The public metadata cache grants no user access by itself.
- No unresolved implementation blockers or known schema/interface conflict in
  this base. Shared `paper_versions` schema lives in `T04_arxiv.sql`; subsequent
  nodes should reference it rather than introduce another source entity.

## Review 1 fix — legacy subject-class aliases

The P2 finding in `ParseID` is addressed: redundant subject classes on legacy
`math`, `cs`, `nlin` and `q-bio` IDs are removed before HTTP parameters, metadata
comparisons, canonical links, cache keys and source IDs are generated. Versions
remain unchanged. A suffix on another archive is rejected. The rule follows
the [arXiv interacting-services contract](https://info.arxiv.org/help/arxiv_identifier_for_services.html).

The HTTP/SQLite integration now covers all four archives. It first requests
the subject-class alias and observes only the canonical ID at the provider
boundary. Responses deliberately mix an alias Atom ID with canonical links.
Equivalent bare, prefixed and PDF URL forms resolve to the same paper/version,
reuse request cache keys and retain one persisted source row per version.
