## Реализация

Обычный `cmd/paper-scout` включает memory в существующий AgentRunner и
researchapp. Recall вопроса выполняется до первого outer DeepSeek request;
после первого содержательного analysis — ещё один recall по содержанию B.
Никакого дополнительного generation client, agent framework, loop или
необязательного tool вместо автоматической точки не добавлено.

Снимки text/hash/revision/provenance/mode сохраняются на run атомарно с public
`memory_recalled`; данные передаются модели после статических правил как
недоверенные. Лимиты: 2 точки, 30 секунд на recall, 5 разных origins, общий JSON
<=12000 Unicode-символов (первая точка <=6000), existing run/token/request caps.
T19 search сохраняет полные группы обязательных annotations отдельно от
публичной дедуплицированной выдачи: дальнейшее сокращение prompt не теряет общую
correction, если другая группа была пропущена. Непомещающиеся группы пропускаются
целиком с явным reason. Ошибка памяти — `unavailable`, не пустая история.

Существующий Report получает nullable typed `research_memory`: `recalled`
отличается от проверенных `referenced`. `[memory:id]` требует выдачи **этому run**
и принадлежности owner; invalid/foreign/owned-but-unissued markers заменяются,
ограничение явное. Report/memory metadata/terminal commit остаются одной
транзакцией; отмена не создаёт report. Снимки прежних runs не переиспользуются
как текущие annotations. Поля Hit/Origin T19 сохранены через aliases.

Capture происходит после report commit, без DeepSeek; исходный pending job уже
существует в той же транзакции отчёта. Сбой capture сохраняет report и public
pending diagnostic; следующий bounded recall восстанавливает проекцию без
платного replay. Memory read/write/embedding логируются отдельно от DeepSeek
usage без текстов, векторов и секретов. `RESEARCH_MEMORY_ENABLED=false` даёт
явный production control без automatic recall/capture; по умолчанию true.

Точный Go/JSON/бюджетный контракт дописан в [research-memory.md](../research-memory.md).
