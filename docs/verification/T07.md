# T07 — Диалоги, run, история, события и отмена

Дата: 2026-10-18. Ветка `dag/t07`.
Base: `b1bdd59f41da9c4ec7ef984b6574cb48536cbd19`.

Реализованы миграция `T07_runs.sql`, owner-scoped store, HTTP-маршруты
диалогов/run/истории/событий/отмены, lifecycle service для подключения будущего
worker и recovery до открытия HTTP. Интерфейсы и точные ответы описаны в
[runs.md](../runs.md).

Создание run, пользовательское сообщение и queue event транзакционны.
Idempotency проверяется до ограничений пула, включая terminal/interrupted run.
Уникальный индекс ограничивает активные run одним на диалог; транзакционная
проверка ограничивает весь Go-процесс двумя run, включая queued. Composite
foreign keys не допускают связи с чужим диалогом/run. Состояние и terminal
event обновляются вместе. Отмена сохраняется до context cancel worker;
completion после сохранённой отмены становится cancelled. Terminal run
не меняется при повторной отмене/завершении/recovery.

Приватная история сохраняет content/reasoning/tool calls/tool results/provider
records и seq. HTTP выбирает только user/assistant text и публичные payloads
событий. Pagination ограничена 100 элементами. Неоконченные run восстанавливаются
как interrupted с причиной и событием; автоматического replay нет.

## Выполненные проверки

Окружение: `go1.26.2-X:nodwarf5 linux/amd64`, закреплённый
`modernc.org/sqlite v1.60.1`. Все команды запускались из T07. `GOCACHE`,
`GOMODCACHE`, `GOPATH`, `TMPDIR` находились под `.bb/runtime/t07` этого worktree;
сценарии T01/T02 использовали ссылки из собственного runtime этого worktree
на тот же локальный кэш. Исходный кэш T02 только прочитан: публичные зависимости
скопированы в T07 после задержки Go proxy, сборки продолжены с `GOPROXY=off`.

- `GOPROXY=off python3 integration/runs.py`: успешно. Собирает production
  entrypoint и Go companion с `go build -race`. Использованы реальные
  auth/store/research/httpapi, SQLite и loopback HTTP; race detector не сообщил
  ошибок. Временные credentials генерируются сценарием, не печатаются.
- Два аккаунта: собственные диалоги и история; чужие и отсутствующие ресурсы
  недоступны. Без bearer — 401; чужие conversation/run/events/cancel и создание
  run в чужом диалоге — 404. Инъекция user_id отклоняется.
- 16 параллельных повторов одного request ID дают один run, сообщение и queue
  event. Другое message с тем же ID даёт 409; восемь разных request ID в одном
  диалоге дают один 202 и семь 409. Два пользователя заполняют общий пул;
  третий run получает 429, повтор существующего запроса всё ещё успешен.
- Queued отменяется сразу; повтор отмены не меняет timestamps/events.
  Running отмена сохраняется и сигнализирует execution context, оставаясь
  активной до Finish. Чужая отмена не сигнализирует worker; completion не
  перезаписывает сохранённую отмену. Проверены partial/failed/completed.
- Execution context переживает отмену короткого request context, имеет deadline
  15 минут и отменяется server context. Повтор Start отвергается. Поздняя запись
  в terminal run отвергается.
- Сгенерированные protocol records с assistant tool call, reasoning, provider
  fields и tool result сохраняются/читаются из SQLite. Это проверка хранения,
  **не** live-вызов модели или инструмента. Sentinel-поля и приватный tool result
  отсутствуют в HTTP истории/событиях; публичный assistant text доступен.
- 12 конкурентных append событий дают уникальный возрастающий seq. Проверены
  event cursor, пустая страница, пагинация сообщений, 103 диалога в нескольких
  страницах, ограничения вводов/страниц, SQLite integrity и foreign_key_check.
  Прямые попытки нарушить composite FK и unique active index отвергнуты SQLite.
- Production-сервер остановлен SIGKILL с queued run, затем запущен дважды:
  история, auth и terminal run сохранены; незаконченные run становятся
  interrupted с единственным terminal event. Повтор request ID не запускает
  работу; явный новый request ID разрешён.
- Companion-процесс создал run через настоящий Service.Create/Start, сохранил
  сообщения и был остановлен SIGKILL при подтверждённом в SQLite running.
  Следующий старт production entrypoint восстановил interrupted, timestamps
  и сохранённую историю. Дополнительно Go companion проверил reopen/recovery
  одновременно queued и running, повтор recovery и сохранение completed usage.
- `GOPROXY=off python3 integration/accounts.py`: успешно; seed, вход/выход,
  изоляция профилей, strict JSON, credentials hashing, restart и expiration.
- `GOPROXY=off python3 integration/foundation.py`: успешно; health/readiness,
  FTS5/BM25, WAL, миграции/restart, drift rejection и безопасная конфигурация.
- `go vet -mod=readonly ./...` с локальными env/cache и `GOPROXY=off`: успешно.
- `go mod verify` с тем же окружением: `all modules verified`.
- `gofmt -l cmd internal integration`, `git diff --check`: успешно, вывода нет.
- `rg --files -g '*_test.go' -g '*_test.dart' -g '!**/.bb/**'`: файлов нет.
  Unit/widget tests не создавались.

## Границы результата

T07 готовит сохранение и lifecycle, а не AgentRunner/research execution.
Новые HTTP run остаются queued до исполнителя T09/T12. Отчёты, coverage,
контекст из coherent completed turns и финализация отчёта — последующие ноды;
`report_id` пока null. Проверка хранения generated provider-shaped records
не заменяет live DeepSeek evidence. Реальные DeepSeek/arXiv/Ollama, retrieval,
Flutter, устройство и видео здесь не запускались и не заявляются проверенными.
Они не нужны для критерия выхода T07, внешних credentials-блокеров нет.

Общий dotenv не читался. Все БД, runtime и build files находятся только в T07,
сценарии удалили временные БД и credentials; игнорируемые build caches остались.
Нет дополнительных потоков, push/deploy/merge или изменений root checkout.
Это результат implement; два независимых review цикла и simplify выполняет
координатор после передачи коммита.
