## Реализовано

`internal/researchmemory`: owner-scoped эпизоды из прежних reports и атомарные
method/result/limitation cards из существующих Analysis; приоритет Synthesis,
иначе только успешные reading segments. Evidence проверяется по исходному
chunk/document, coverage не повышается. ADD/NOOP сохраняет все origins;
противоречащие результаты разных papers сосуществуют. DeepSeek не вызывается.

Миграция `T19_research_memory.sql`: durable capture jobs, origins, revisions,
source history каждой явной note edit/clear, passages/FTS5 и private embeddings.
Идемпотентный capture/rebuild сохраняет user corrections/exclusions и IDs.
Report commit не зависит от памяти: pending job создаётся SQL-триггером, bounded
Refresh восстанавливает пропуск после сбоя. Note меняет generation и синхронно
удаляет прежние passages/vectors. Hash+revision проверяются после inference.

Поиск: настоящий SQLite BM25 top20 + Qwen3 exact cosine top20 + RRF k=60;
owner/cutoff/current-run/exclusion фильтруются до top-k. Не более 5 origin-групп,
12000 Unicode-символов текстов включая детерминированные notes/corrections;
индексация одним batch<=32. Неполнота индекса, capture backlog и ошибки явные.
Новые authenticated POST search / GET / PATCH зарегистрированы через обычный
httpapi.NewWithRuns (и потому доступны в cmd/paper-scout). Старые callers
совместимы. AgentRunner/Flutter не менялись.

Точный контракт и рекомендации T20/T21:
[research-memory.md](../research-memory.md#реализованный-gohttp-контракт-t19).
Консервативный owner-wide guard исключает свободные эпизодические пересказы
после note или disputed/excluded записи: так поздний отчёт не возвращает старую
заметку/ошибку через другую статью. Claims с origins/актуальными annotations
сохраняют доступ к прежним исследованиям; оригинальные отчёты не переписываются.

## Границы доказательств

Это приёмка T19 на синтетических persisted исследованиях и реальной Qwen3,
не научная проверка фактов, не arXiv/DeepSeek-проход и не Flutter/device demo.
Семантическая релевантность dense top-k не является доказательством. Генерация
сравнения A/B, автоматический recall, immutable run snapshots и проверенные
memory citations — T20; UI — T21; production live A→note→restart→B и новое видео —
T22. Здесь они не заявляются выполненными. Новых agent libraries нет.

## Review 1 — исправлены три ошибки recall

- P1: annotations раскрывает обязательные поправки присоединённых user_note.
  Search рассчитывает размер всей группы claim → note → correction до публикации;
  disputed note больше не возвращается через научную карточку без своей правки.
- P2 (origins): полный набор origins используется только для обнаружения связей.
  Annotations наследуют уже ограниченный набор provenance основного hit. Поправка
  седьмого эпизода не скрывается, но опубликованный контекст целиком содержит не
  более пяти report origins; семь durable origins карточки остаются в БД/GET.
- P2 (backlog): pending/stale note даёт явный ErrPending / HTTP503 memory_pending,
  retryable=true. До публикации проверяются pending jobs связанных papers, в том
  числе когда новая note ещё не имеет проекции. POST search больше не отвечает
  404 при незавершённой проекции и не отдаёт claim без обязательной заметки.

Адресная интеграция `integration/researchmemory/review1.go` включена в обычный

во время query inference; повтор после обоих pending503; консолидация в семь
