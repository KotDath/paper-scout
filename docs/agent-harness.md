# Собственный agent harness

## Основные сущности

`DeepSeekClient` — единственная реализация вызова DeepSeek. `AgentSession` — долговечная сущность нашего приложения: владелец, диалог, история, выбранные источники и запуски. `AgentRunner` исполняет один запрос пользователя, используя эту сессию и реестр исследовательских tools. `ResearchAnalyzer` читает части статей через тот же клиент; это ограниченная обработка текста, а не второй автономный агент.

```text
DeepSeekClient.Complete(ctx, request) -> response
EmbeddingClient.Embed(ctx, mode, texts) -> vectors
AgentRunner.Run(ctx, owner, session, run) -> result
Tool.Execute(ctx, owner, run, validatedArgs) -> toolResult
```

API-клиент не владеет пользовательской историей. Хранением и подбором истории управляет AgentSession; клиент отправляет построенный `messages` и разбирает ответ провайдера. В Chat Completions контекст нужно передавать в запросах самостоятельно. [DeepSeek multi-round chat](https://api-docs.deepseek.com/guides/multi_round_chat/).

## Контракт DeepSeek

Запрос идёт на `/chat/completions`; настройки base URL, model и ключ задаются серверу. Базовый URL по умолчанию — `https://api.deepseek.com`. Используются `messages`, функции в `tools`, `tool_choice=auto` и явные ограничения ответа. Начальная реализация — `stream=false`, thinking отключён для простоты и скорости; конкретное имя доступной модели задаётся конфигурацией, а не историческим alias в коде.

Assistant message сохраняется с `content`, `tool_calls` и, если получено, отдельным `reasoning_content`. Результат каждого инструмента возвращается как `role=tool` с соответствующим `tool_call_id`. Аргументы tool calls проверяются сервером. [Контракт Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/), [tool calling](https://api-docs.deepseek.com/guides/tool_calls/).

Если thinking включат конфигурацией, harness сохраняет и возвращает требуемое провайдером `reasoning_content` вместе с историей tool-enabled запросов. Оно не становится обычным ответом пользователя и не показывается в UI. Для реализации необходимо следовать актуальному [thinking contract](https://api-docs.deepseek.com/guides/thinking_mode/), а не старым примерам R1.

## Цикл выполнения

```text
загрузить сессию, проверить владельца и единственный активный run
добавить пользовательский запрос и событие старта
пока бюджет и отмена позволяют:
    построить контекст без разрыва assistant/tool связей
    вызвать DeepSeekClient и учесть попытку, время и usage
    сохранить исходное assistant message
    если ответ усечён или провайдер завершил его с ошибкой:
        завершить/ограниченно повторить по политике; tools не исполнять
    если tool calls отсутствуют:
        проверить ответ и адресуемость ссылок
        сохранить отчёт, источники, покрытие и terminal status
        закончить run
    для каждого tool call в порядке модели:
        проверить имя, JSON, ограничения аргументов и ownership
        выполнить tool с deadline и общим бюджетом run
        сохранить результат с исходным tool_call_id
при отмене/лимите/ошибке сохранить terminal event и доступный результат
```

Невалидные аргументы возвращаются модели как структурированная ошибка инструмента, не передаются дальше. Усечённый ответ (`finish_reason=length`) не исполняет даже внешне похожие на целые tool calls. Отмена не оставляет неучтённых исполнений; для не начатых calls сохраняется `cancelled`. Незавершённые ходы не подмешиваются в следующую беседу как успешно завершённые.

## Инструменты первой версии

| Tool | Аргументы | Результат и границы |
| --- | --- | --- |
| `search_papers` | query, необязательный период, limit до 10 | Реальные arXiv IDs, версии, заголовки, аннотации и ссылки; общий кэш и limiter |
| `import_paper` | arxiv_id с необязательной версией | Источник, полный извлечённый текст или причина fallback; indexing status |
| `analyze_paper` | paper_version_id, исследовательский вопрос | Разбор всего извлечённого текста в пределах бюджета, evidence IDs и coverage; бюджет не обходится вложенными LLM-вызовами |
| `search_library` | query, необязательные paper IDs, limit до 8 | Гибридная выдача, режим retrieval, свидетельства и координаты |
| `read_passages` | разрешённые evidence IDs или диапазон | Исходные фрагменты и соседний контекст с ограничением размера |

Ownership и run ID передаются сервером вне генерируемых аргументов. Инструментов shell, произвольного HTTP и исполнения кода нет. Сохранение готового отчёта выполняет приложение при завершении хода, а не отдельный необязательный вызов модели. Изменение интересов, заметок и отметок прочтения — явные действия пользователя через API.

## Анализ статьи

Текст разбивается на последовательные пакеты по разделам. Каждый пакет содержит источники и локальные координаты; запрос с отключёнными tools извлекает методы, экспериментальные результаты, ограничения и подтверждающие passages. Наблюдения и успешные диапазоны сохраняются. Синтез объединяет наблюдения и возвращает ссылки на исходный текст, а не только на промежуточное резюме.

Если статья помещается целиком, отдельная пофрагментная обработка не нужна. При больших статьях суммаризация не исключает части текста: при невозможности покрыть все части запуск сообщает `partial`. Повторный успешный анализ диапазона не увеличивает покрытие сверх 100%.

## Начальные бюджеты

Эти пределы — конфигурация прототипа, которую проверяют на реальном проходе; они не являются оценкой скорости или цены модели.

| Предел | Начальное значение |
| --- | --- |
| Активные run | 1 на диалог, 2 на весь сервер |
| Внешние tool calls | 24 на run |
| Все DeepSeek requests, включая анализ и retries | 32 на run |
| Все завершённые DeepSeek prompt + completion tokens | 250000 на run; проверка после каждого ответа |
| Ответ одного DeepSeek request | до 4096 output tokens |
| Максимальное время run | 15 минут |
| Один DeepSeek request | до 120 секунд |
| Один source download | до 60 секунд, PDF до 30 MiB |
| `pdftotext` | до 30 секунд на документ |
| Точно одинаковый tool call | не более 2 исполнений в run |
| Отобранные статьи | до 3; приёмка требует полного разбора хотя бы одной |

Токенный предел по usage не гарантирует остановку точно перед превышением: вход следующего запроса оценивается до отправки, фактический usage записывается после ответа. При неизвестном usage после сетевого обрыва сохраняется неопределённость. Денежная стоимость не показывается как точная без настроенных актуальных тарифов.

## История и контекст

Сообщения и события сохраняются в порядке `seq`; исходные provider fields отделены от пользовательской проекции. Для повторного вопроса используются завершённые ходы, профиль и ссылки на ранее полученные результаты. Тексты извлекаются из библиотеки по необходимости, вместо многократной вставки всех PDF в историю.

Контекст имеет задаваемый предел. Если он не помещается, прототип возвращает `context_limit` и предлагает новый диалог с сохранённой библиотекой. История в БД не удаляется. Автоматическая compaction отложена; её будущая реализация обязана сохранять исходные события и целые пары tool call/result.

Отчёт имеет разделы: вопрос и область поиска; выбранные работы и основания выбора; методы и результаты; ограничения источников; выводы агента; что читать дальше. Фактические абзацы ссылаются на evidence IDs, которые UI раскрывает в доступный текст с страницей/разделом и ссылкой на оригинал.
