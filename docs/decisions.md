# Решения по Paper Scout

Продуктовый объём согласован в интервью. Ниже отдельно отмечены обязательные решения пользователя и выбранные технические решения для реализации. Открытых продуктовых вопросов нет; конкретные версии зависимостей фиксируются при создании проекта.

## Обязательные решения

| ID | Решение | Следствие |
| --- | --- | --- |
| U01 | Выполнить только день 35 | Удалены требования поддержки из дня 33; день 34 не входит |
| U02 | Как можно быстрее получить прототип | Один агент, исследование по запросу, один источник публикаций |
| U03 | Несколько пользователей, достаточно двух аккаунтов | Вход и изоляция обязательны; регистрация не нужна |
| U04 | Долговременная память AI-агентов | Это тема реальной автоматизируемой работы |
| U05 | Go API и Flutter | Клиент отвечает за интерфейс, сервер — за AI и данные |
| U06 | Локально на ноутбуке | Без обязательной облачной инфраструктуры |
| U07 | Android как тестовое окружение | С него проверяем приложение и записываем видео |

| U12 | Запрет юнит-тестов | Разрешены интеграционные тесты и сквозные проверки |
| U13 | Гибридный RAG с embedding-моделью | Лексическая и векторная ветки обязательны |

## Технические решения

| ID | Выбор | Причина и граница |
| --- | --- | --- |
| A01 | Модульный монолит Go, `net/http` | Один локальный процесс и простой запуск |
| A02 | SQLite через `database/sql` и `modernc.org/sqlite` | БД в одном файле без отдельного сервера; выбранная версия проверяется на FTS5 при реализации |
| A03 | arXiv как первый источник | Метаданные и доступные тексты научных работ без отдельной CRM или каталога |
| A04 | HTML, затем PDF и `pdftotext` | Два пути к тексту без OCR; ошибки не скрываются |
| A05 | FTS5 + Qwen3 Embedding через существующую Ollama + RRF | Гибридный retrieval; векторы в SQLite, exact search в Go для небольшой библиотеки |
| A06 | Нестриминговый запрос к DeepSeek; polling прогресса в UI | Проще собрать правильные tool calls и восстанавливать экран |
| A07 | Один активный запуск на диалог и два на сервер | Достаточно двух пользователей, ограничивает расход и гонки |
| A08 | Долговечная история и явные пределы контекста | Сохранение не зависит от окна модели; сложная compaction отложена |
| A09 | Непрозрачные bearer-сессии | Простой настоящий вход без OAuth и JWT-инфраструктуры |
| A10 | Ответы на русском, источники преимущественно на английском | Соответствует рабочему сценарию пользователя |

Решения A01–A10 задают конкретный путь реализации; заменять их следует только при выявленной технической проблеме и с обновлением затронутых документов. Ограничения U01–U14 сохраняются.

## Результат grilling

Дерево решений закрыто по ветвям: цель → день 35 → исследование по запросу; пользователи → два аккаунта → отдельные данные; источники → полный доступный текст → явный fallback на аннотацию; выполнение → локальный Go → DeepSeek Chat Completions → собственный harness; интерфейс → Flutter → Android-эмулятор; доказательства → интеграционные проверки → реальный проход → видео и код.

Реализация не входит в сделанные изменения документации. Порядок следующей работы определён [DAG](implementation-dag.md).
