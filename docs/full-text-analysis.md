# T10: полный доступный текст и покрытие

`research.Analyzer` — ограниченный обработчик статьи, а не автономный агент.
Он использует T05 `documents.Service` и T07 `store.Store`, без отдельной
реализации HTTP-провайдера, retrieval или агентной библиотеки.

## Подключение в T11

1. После импорта сервер вызывает `SelectSource(ctx, owner, runID, paperID,
   selectionReason)`. Метод проверяет владельца, running/cancel_requested и
   ограничение трёх источников. Это явное предоставление доступа к публичному
   документу в конкретном запуске. Один лишь технический кэш доступа не даёт.
   Таблица `run_sources` принадлежит миграции `T10_analysis.sql`; T11 использует
   её, не создаёт вторую сущность выбора источников.
2. `Analyze(ctx, owner, runID, documentID, question, budgetedComplete)` получает
   серверные owner/runID, точный ID документа и обязательный callback.
   **Callback должен использовать тот же экземпляр счётчиков запросов, tokens,
   deadline и контекста, что AgentRunner этого запуска**, и тот же
   `DeepSeekClient.Complete`. Он резервирует бюджет до отправки, оценивает весь
   prompt плюс output, учитывает `Attempted`, сохраняет фактический usage после
   ответа, включая ошибочный. NULL usage означает неизвестную стоимость.
   При отказе до отправки возвращаются `ErrAnalysisBudget` или
   `ErrAnalysisContext`, `Attempted=false`. При превышении бюджета после ответа
   возвращаются исходные response/usage и ошибка. Callback выполняет не более
   одной provider attempt за вызов; анализатор сам retries не делает.
3. Нельзя передавать непосредственно `client.Complete` в инструмент
   `analyze_paper`: это обошло бы общий бюджет. Прямой клиент не создаётся
   анализатором и не используется как fallback. Проверка совместного бюджета
   реального AgentRunner остаётся T11; интеграционный gateway T10 показывает
   контракт, но не заменяет эту интеграцию.
4. `Analysis(ctx, owner, analysisID)` читает сохранённый результат; повторных
   сетевых вызовов нет. Чужой запуск, результат или невыбранный источник дают
   `store.ErrNotFound`. Позднейшая HTTP-проекция должна преобразовать это в 404.
   HTTP маршруты и UI не входят в T10.

Каждая попытка анализа имеет отдельный ID и вопрос. Успешные диапазоны другого
вопроса/документа/запуска не переиспользуются для повышения покрытия. Для одного
run/document запрещены одновременно незавершённые анализы. Повторный анализ
после завершения — новый платный вызов в рамках того же общего бюджета.

## Что получает модель

Если текст помещается в `MaxSegmentRunes`, он передаётся одним запросом. Иначе
анализатор проходит все диапазоны по порядку, предпочитая границы разделов или
страниц. Каждый пакет — последовательные исходные passages с существующими
T05 evidence IDs, Unicode offsets, страницами/разделами и URL оригинала.
Перекрывающиеся retrieval chunks обрезаются при передаче, так что текст не
пропускается и не считается дважды. Пакеты готовятся по одному, после проверки
локального MaxRequests и состояния run; обход разделов и chunks проверяет
context. Курсоры движутся вперёд, будущие пакеты не материализуются. Evidence
использует уже сохранённый текст chunk; для обрезки декодируется только chunk,
а не вся статья. Общая загрузка исходного документа из SQLite остаётся линейной
по размеру. Нет отбора по релевантности или RAG.

Системная инструкция объявляет статью данными и запрещает следовать вложенным
указаниям. Tools отсутствуют во всех запросах. Ответ содержит массивы methods,
results, limitations с короткими наблюдениями и evidence IDs. Все IDs должны
принадлежать переданному пакету. После нескольких частей отдельный запрос
объединяет **все** наблюдения, сохраняя ссылки на исходные evidence. Если вход
синтеза превышает предел, он не обрезается: результат остаётся partial с
`context_limit`. Для одного пакета его наблюдения уже являются итогом.

Пределы по умолчанию: 36000 code points текста на пакет, 48000 на JSON синтеза,
12 вложенных запросов, до 2048 output tokens. Это дополнительные ограничения;
они не создают второй независимый бюджет запуска. Допустимы меньшие пределы.
Подсчёт code points не является оценкой токенов модели. Полный prompt должен
проверять общий gateway, включая metadata, вопрос и JSON-разметку.

## Долговечность и честность

`paper_analyses` хранит вопрос, точный document ID, статус и итог. В
`analysis_segments` до сети записываются полный вход, SHA-256 входа, диапазон,
IDs и pending; после — структурированное наблюдение, usage/attempted и
succeeded/failed. Reasoning и сырые provider bodies в эти таблицы не попадают.
Сетевые вызовы выполняются вне транзакций. Ошибка и отмена записываются свежим
persistence context с пределом 5 секунд. Pending после обрыва остаётся
неопределённой попыткой с неизвестным usage; покрытие за неё не начисляется.

Покрытие — длина объединения успешных reading ranges в точном извлечённом
тексте. Synthesis не добавляет покрытие. Повтор диапазона не превышает 100%.
`complete` требует покрытия всего непустого full_text и успешного синтеза.
Лимит, ошибка, truncation, неизвестный usage, недопустимый evidence и отмена
дают `partial`, даже если чтение завершилось, а синтез не удалось выполнить.
Успешная аннотация получает только `abstract_only`; пустой/failed документ —
`none` с `text_unusable`. Технические extraction warnings сохраняются отдельно.
События `analysis_progress` передают фактические covered_runes и количество
успешных частей, а не оценку скорости модели. Предварительный `total_parts`
больше не вычисляется: он требовал бы обхода ещё не запрошенных пакетов;
`successful_parts`, `covered_runes` и `total_runes` сохраняют фактический прогресс.

После hard crash `Analysis` восстанавливает успешный префикс из БД и сообщает
partial/run_interrupted после T07 RecoverRuns. Возобновления платных вызовов
нет. Результат завершённого анализа и его evidence сохраняются при рестарте.

Evidence в результате раскрывает исходный chunk, страницу/раздел и URL;
PDF получает `#page=N`, HTML — существующий исходный URL и отдельный section,
без выдуманного fragment ID. Проверка IDs подтверждает адресуемость и область
доступа, а не научную истинность. Семантику утверждений проверяют по оригиналу.
Изображения, формулы и полное восстановление таблиц не обещаются; OCR нет.

## Проверки

```sh
python3 integration/analysis.py
DEEPSEEK_MODEL=deepseek-flash DEEPSEEK_THINKING=disabled \
  python3 integration/analysis.py --live \
  --env-file /home/kotdath/omp/personal/ai/paper-scout/.env
```

Локальный режим: внешние HTTP source/provider fixtures, настоящие Go-клиенты,
HTML extraction, Poppler, production migrations и SQLite. Live: реальные arXiv
metadata/full text и DeepSeek, до 8 запросов с 1536 output tokens, общий предел
180000 tokens, 12 минут, без retries. Credentials загружает Go-процесс по пути;
значения не печатаются. Caches, binary, DB и исходные документы находятся в
`.bb/runtime/t10` этого worktree; временные данные удаляются runner-ом.
Параметры `--paper` и `--segment-runes` позволяют выбрать настоящую статью и
размер частей для ограниченного live-прохода (подтверждён также
`--paper 1301.3781v1 --segment-runes 12000`).
Фактический результат и ограничения: [verification/T10.md](verification/T10.md).
